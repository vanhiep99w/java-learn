## 1. Framework gọi method 1 triệu lần qua reflection — chậm 10×

Reflection API cho code **thao tác với metadata của class** (lookup method/field, invoke, sinh class runtime) — là cỗ máy "meta-programming" đứng sau mọi framework lớn (Spring, Hibernate, Jackson). Nó quan trọng vì không có reflection thì không thể có AOP, ORM mapping tự động, hay serialization; nhưng nếu dùng ngây thơ trong hot path, nó chậm hơn gọi trực tiếp **10–25×**.

```java
for (Row row : resultSet) {    // 1 triệu rows
    Object entity = clazz.getDeclaredConstructor().newInstance();
    for (Field field : fields) {
        field.setAccessible(true);
        field.set(entity, row.get(field.getName()));  // reflection set
    }
}
```

Profiler: 70% thời gian trong `Method.invoke()` / `Field.set()`. Direct setter call: 3ns. Reflection: 30-80ns — **10-25× chậm hơn**.

```text
Benchmark                    Mode  ns/op
directCall                   avgt    3.2
reflectionFirstTime          avgt  850.0    ← inflation + access check
reflectionAfterInflation     avgt   28.5    ← generated accessor
reflectionCached+Accessible  avgt    8.1    ← tốt nhất reflection đạt được
```

> [!IMPORTANT]
> Reflection không "chậm lúc nào cũng chậm". Sau **inflation** (15 lần gọi), JVM sinh bytecode accessor gần bằng direct call. Cái đắt là: access check mỗi lần, method lookup nếu không cache, và JIT khó inline qua invoke.

Phần còn lại của doc sẽ đi qua: `Class`/`Method`/`Field` dưới hood (§2) → `Method.invoke()` và accessor delegation (§3) → cơ chế inflation native → bytecode (§4) → phân tích performance cost (§5) → `setAccessible(true)` & module system (§6) → Dynamic Proxy sinh class runtime (§7) → `InvocationHandler` dispatch hub (§8) → mổ xẻ bytecode `$Proxy0` (§9) → use cases AOP/RPC/lazy loading (§10) → CGLIB vs JDK Proxy (§11) → MethodHandle thay thế hiện đại (§12) → cheat sheet (§13).

## 2. Reflection cơ bản — Class, Method, Field dưới hood

```java
// Class object — metadata của mỗi class trong JVM
Class<?> clazz = MyEntity.class;  // hoặc obj.getClass(), Class.forName(...)

// Method lookup
Method m = clazz.getDeclaredMethod("setName", String.class);
// Bên trong: tìm trong class metadata (constant pool → method descriptor)

// Field lookup
Field f = clazz.getDeclaredField("name");

// Constructor
Constructor<?> ctor = clazz.getDeclaredConstructor();
```

**Bên trong `getDeclaredMethod()`:**

```java
// java.lang.Class (simplified):
public Method getDeclaredMethod(String name, Class<?>... parameterTypes) {
    Method[] methods = privateGetDeclaredMethods(false);  // lấy từ cache hoặc JVM
    // Linear search matching name + params
    for (Method m : methods) {
        if (m.getName().equals(name) && arrayContentsEq(parameterTypes, m.getParameterTypes()))
            return getReflectionFactory().copyMethod(m);  // trả COPY (mỗi lần gọi tạo mới!)
    }
    throw new NoSuchMethodException(...);
}
```

> [!WARNING]
> `getDeclaredMethod()` trả **copy mới** mỗi lần gọi (để mỗi caller có thể setAccessible riêng). **Luôn cache** Method/Field object nếu gọi nhiều lần — lookup cost O(n methods) + allocation.

## 3. Method.invoke() — accessor delegation pattern

```java
// Method.invoke():
public Object invoke(Object obj, Object... args) throws ... {
    if (!override) {
        Class<?> caller = Reflection.getCallerClass();
        checkAccess(caller, clazz, obj, modifiers);  // access check mỗi lần
    }
    MethodAccessor ma = methodAccessor;  // delegate
    if (ma == null) {
        ma = acquireMethodAccessor();    // lần đầu: tạo accessor
    }
    return ma.invoke(obj, args);         // gọi thực sự
}
```

`MethodAccessor` interface có 2 implementation:
1. **NativeMethodAccessorImpl** — gọi qua JNI (native). Dùng lần đầu.
2. **GeneratedMethodAccessorXXX** — generated bytecode. Nhanh, sau inflation.

## 4. Inflation — từ native stub đến generated bytecode

### 4.1. Tại sao không generate ngay từ đầu?

Generate bytecode tốn ~1ms (define class + verify + link). Nếu method chỉ invoke 1-2 lần (startup config, test) → generate lãng phí. Native stub chậm hơn per-call nhưng start-up cost = 0.

### 4.2. Inflation threshold

```java
// sun.reflect.ReflectionFactory:
private static int inflationThreshold = 15;  // -Dsun.reflect.inflationThreshold=15

// NativeMethodAccessorImpl.invoke():
public Object invoke(Object obj, Object[] args) {
    if (++numInvocations > inflationThreshold) {
        // Generate bytecode accessor class
        MethodAccessorImpl acc = MethodAccessorGenerator.generate(...);
        parent.setDelegate(acc);  // swap delegate
    }
    return invoke0(method, obj, args);  // native call
}
```

### 4.3. Generated accessor bytecode

```java
// GeneratedMethodAccessor42 (generated at runtime):
public class GeneratedMethodAccessor42 extends MethodAccessorImpl {
    public Object invoke(Object obj, Object[] args) {
        // Direct call — NO native, NO reflection overhead
        return ((MyEntity) obj).setName((String) args[0]);
    }
}
```

Sau inflation: `Method.invoke()` → `GeneratedAccessor.invoke()` → **direct method call** (cast + invoke). JIT có thể inline toàn bộ chain.

> [!TIP]
> `-Dsun.reflect.inflationThreshold=0` → generate ngay lần đầu (skip native). Dùng khi biết method sẽ invoke nhiều (ORM, serialization). Trade-off: startup chậm hơn, steady-state nhanh hơn.

## 5. Performance cost — tại sao reflection chậm (và khi nào không)

| Cost source | Ảnh hưởng | Mitigation |
|------------|-----------|------------|
| **Access check** mỗi invoke | ~5-10 ns | `setAccessible(true)` — skip check |
| **Boxing** (primitive → Object[]) | ~5 ns per arg | Không tránh được với Method.invoke |
| **Method lookup** (getDeclaredMethod) | ~200-500 ns | Cache Method object |
| **Native stub** (trước inflation) | ~40-80 ns | Gọi > 15 lần → auto inflate |
| **JIT barrier** (invoke qua accessor) | Khó inline | MethodHandle + invokeExact (JDK 7+) |
| **Array allocation** (varargs Object[]) | ~10 ns | Reuse array nếu có thể |

**Benchmark: reflection vs direct (JDK 17, JMH):**

```text
Method                              ns/op   Speedup vs raw reflect
directMethodCall                      2.8   35x
methodHandle.invokeExact()            3.1   32x  ← gần bằng direct
reflectCached+Accessible+Inflated     8.1   12x
reflectCached+Accessible              28.5   3.5x  (pre-inflation)
reflectNoCache                       520.0   1x    (worst case)
```

> [!IMPORTANT]
> Với optimized reflection (cache Method + setAccessible + inflated): chỉ chậm ~3× so với direct call. MethodHandle gần bằng direct call. "Reflection chậm" đúng cho naive usage, SAI cho optimized usage.

## 6. setAccessible(true) — bypass access check

```java
Method m = clazz.getDeclaredMethod("privateMethod");
m.setAccessible(true);   // bypass access check → skip checkAccess() mỗi invoke
m.invoke(obj);           // gọi private method — no IllegalAccessException
```

**JDK 9+ Module System impact:**

```java
// Module java.base:
m.setAccessible(true);  // throws InaccessibleObjectException!
// Cần: --add-opens java.base/java.lang=ALL-UNNAMED
```

`setAccessible(true)` trên Method object:
- Set `override = true` → skip access check trong `invoke()`.
- **Không** thay đổi method gốc — chỉ ảnh hưởng **copy này** (vì getDeclaredMethod trả copy).
- JDK 9+: blocked bởi module system cho non-exported packages.

> [!NOTE]
> Performance impact: bỏ access check tiết kiệm ~5-10 ns/call. Khi gọi triệu lần (ORM, serializer) → đáng kể. Mọi framework (Spring, Jackson, Hibernate) đều `setAccessible(true)`.

## 7. Dynamic Proxy — tạo class runtime từ interface

```java
// Tạo proxy cho interface UserService:
UserService proxy = (UserService) Proxy.newProxyInstance(
    UserService.class.getClassLoader(),        // ClassLoader
    new Class<?>[] { UserService.class },      // interfaces to implement
    new MyInvocationHandler(realService)        // handler
);

proxy.findUser("id-123");  // → gọi handler.invoke(proxy, method, args)
```

**Bên trong `Proxy.newProxyInstance()`:**

```java
public static Object newProxyInstance(ClassLoader loader, Class<?>[] interfaces, InvocationHandler h) {
    // 1. Generate hoặc cache proxy Class
    Class<?> cl = getProxyClass0(loader, interfaces);
    // Class name: com.sun.proxy.$Proxy0, $Proxy1, ...

    // 2. Get constructor (InvocationHandler)
    Constructor<?> cons = cl.getConstructor(InvocationHandler.class);

    // 3. newInstance
    return cons.newInstance(h);
}
```

**Proxy class được generate 1 lần** per (ClassLoader + interfaces combination) rồi **cache** trong `WeakCache`. Lần gọi sau: lookup cache → O(1).

## 8. InvocationHandler — dispatch hub

```java
public interface InvocationHandler {
    Object invoke(Object proxy, Method method, Object[] args) throws Throwable;
}
```

```java
public class LoggingHandler implements InvocationHandler {
    private final Object target;   // real object

    public LoggingHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        long start = System.nanoTime();
        try {
            // Before: logging, auth check, transaction begin, ...
            Object result = method.invoke(target, args);  // delegate to real object
            // After: logging, commit, metrics, ...
            return result;
        } catch (InvocationTargetException e) {
            throw e.getCause();  // unwrap
        } finally {
            long elapsed = System.nanoTime() - start;
            log.debug("{}.{}() took {} ns", target.getClass().getSimpleName(), method.getName(), elapsed);
        }
    }
}
```

> [!TIP]
> `InvocationHandler.invoke()` nhận **Method object** → biết chính xác method nào được gọi. Có thể dispatch khác nhau theo method name, annotation, return type... Đây là nền tảng của AOP (Aspect-Oriented Programming).

## 9. Proxy class generated bytecode — mổ xẻ $Proxy0

JVM generate proxy class dạng:

```java
// Generated: $Proxy0 (decompiled)
public final class $Proxy0 extends Proxy implements UserService {
    private static Method m0;  // hashCode
    private static Method m1;  // equals
    private static Method m2;  // toString
    private static Method m3;  // findUser(String)

    static {
        m0 = Class.forName("java.lang.Object").getMethod("hashCode");
        m1 = Class.forName("java.lang.Object").getMethod("equals", Object.class);
        m2 = Class.forName("java.lang.Object").getMethod("toString");
        m3 = Class.forName("UserService").getMethod("findUser", String.class);
    }

    public $Proxy0(InvocationHandler h) { super(h); }

    @Override
    public User findUser(String id) {
        try {
            return (User) h.invoke(this, m3, new Object[]{id});
            //                      ↑      ↑              ↑
            //                   proxy   method         args
        } catch (Throwable t) { throw new UndeclaredThrowableException(t); }
    }

    @Override
    public int hashCode() {
        return (Integer) h.invoke(this, m0, null);
    }
    // ... equals, toString tương tự ...
}
```

**Key observations:**
1. Method objects cache trong **static fields** (lookup 1 lần khi class load).
2. Mỗi interface method → 1 method trong proxy → gọi `h.invoke()`.
3. `hashCode`, `equals`, `toString` của `Object` cũng proxy (dispatch qua handler).
4. Return type: auto-unbox nếu primitive (`(Integer)` → unbox to `int`).

## 10. Use cases: AOP, RPC client, lazy loading, validation

### 10.1. AOP — transaction management (Spring)

```java
// Spring @Transactional dùng proxy:
UserService proxy = (UserService) Proxy.newProxyInstance(..., (obj, method, args) -> {
    if (method.isAnnotationPresent(Transactional.class)) {
        tx.begin();
        try {
            Object result = method.invoke(realService, args);
            tx.commit();
            return result;
        } catch (Exception e) { tx.rollback(); throw e; }
    }
    return method.invoke(realService, args);
});
```

### 10.2. RPC client — Feign/Retrofit style

```java
// Interface → HTTP call:
UserApi api = (UserApi) Proxy.newProxyInstance(..., (obj, method, args) -> {
    String path = method.getAnnotation(GET.class).value();  // "/users/{id}"
    // Replace path params, make HTTP call, deserialize response
    return httpClient.get(baseUrl + resolvePath(path, args), method.getReturnType());
});

api.getUser("123");  // → GET https://api.com/users/123 → deserialize User
```

### 10.3. Lazy loading — Hibernate

```java
// Hibernate lazy proxy: entity chỉ load từ DB khi access field/method
User user = session.load(User.class, id);  // trả proxy, KHÔNG query DB
user.getName();  // → proxy handler: query DB lần đầu, cache, delegate
```

### 10.4. Validation

```java

// @NotNull String name → check null trước invoke
```

## 11. CGLIB vs JDK Proxy — class proxy không cần interface

| | JDK Dynamic Proxy | CGLIB |
|-|-------------------|-------|
| Proxy target | **Interface only** | **Class** (kể cả không có interface) |
| Mechanism | Generate class implements interface | Generate **subclass** (extends target) |
| final method | N/A (interface methods) | ❌ Không proxy được (không override được) |
| Performance | Nhanh (JDK native support) | Nhanh (generated bytecode, không qua InvocationHandler) |
| Dependency | JDK built-in | Thư viện ngoài (cglib / ByteBuddy) |
| Spring default | Khi bean có interface | Khi bean không có interface (hoặc `proxyTargetClass=true`) |

```java
// CGLIB proxy (Spring AOP khi không có interface):
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserServiceImpl.class);  // subclass, không cần interface
enhancer.setCallback((MethodInterceptor) (obj, method, args, proxy) -> {
    log.info("Before: {}", method.getName());
    Object result = proxy.invokeSuper(obj, args);  // gọi method gốc qua super
    log.info("After: {}", method.getName());
    return result;
});
UserServiceImpl proxy = (UserServiceImpl) enhancer.create();
```

> [!NOTE]
> Spring Boot 2.0+ default dùng **CGLIB** (`proxyTargetClass=true`) kể cả khi bean có interface. Lý do: tránh bug khi inject concrete class mà proxy chỉ implement interface. JDK Proxy vẫn dùng được nhưng phải opt-in.

## 12. MethodHandle (JDK 7+) — thay thế hiện đại cho reflection

```java
MethodHandles.Lookup lookup = MethodHandles.lookup();
MethodHandle mh = lookup.findVirtual(String.class, "length", MethodType.methodType(int.class));

int len = (int) mh.invokeExact("Hello");  // 5 — gần bằng direct call
```

| | Reflection (Method.invoke) | MethodHandle |
|-|---------------------------|--------------|
| Access check | Mỗi invoke (trừ khi setAccessible) | **1 lần** tại lookup time |
| Type safety | Runtime (Object[] args) | **Compile-time** (invokeExact) |
| JIT inline | Khó (qua accessor) | **Dễ** (JVM treat như bytecode) |
| Performance | ~8-28 ns | **~3 ns** (bằng direct call) |
| Polymorphic | Không (cùng method cho mọi type) | Polymorphic signature |

```java
// MethodHandle: type-safe, inlinable
MethodHandle getName = lookup.findVirtual(User.class, "getName", 
    MethodType.methodType(String.class));
String name = (String) getName.invokeExact(user);  // compile-time check type

// VarHandle (JDK 9+): thay Unsafe cho field access
VarHandle vh = MethodHandles.lookup().findVarHandle(Counter.class, "count", int.class);
vh.compareAndSet(counter, 0, 1);  // atomic CAS, no Unsafe needed
```

> [!TIP]
> Dùng MethodHandle khi: (1) performance-critical reflection (serializer, ORM), (2) cần JIT inline (hot path), (3) framework mới (không legacy). Dùng Method.invoke khi: (1) code đơn giản, (2) không performance-sensitive, (3) cần flexibility (setAccessible dynamic).

## 13. Tóm tắt — Cheat sheet & 5 nguyên tắc

**Cỗ máy trong 6 dòng:**

```
1. Reflection: Class → getDeclaredMethod → Method.invoke → MethodAccessor → actual call
2. Inflation: lần 1-15 dùng native stub; lần 16+ generate bytecode accessor (~direct call)
3. setAccessible(true): skip access check mỗi invoke; JDK 9+ bị module system chặn
4. Dynamic Proxy: generate $ProxyN class implements interface → dispatch qua InvocationHandler
5. Proxy class cache per (ClassLoader + interfaces); Method objects in static fields
6. MethodHandle: access check 1 lần, JIT inline, type-safe — modern replacement
```

| Operation | Cost (JDK 17) | Notes |
|-----------|--------------|-------|
| Direct call | ~3 ns | Baseline |
| MethodHandle.invokeExact | ~3 ns | Equals direct after JIT |
| Reflection (cached+accessible+inflated) | ~8 ns | 2.5× direct |
| Reflection (cached+accessible, pre-inflate) | ~28 ns | 9× direct |
| getDeclaredMethod (uncached) | ~500 ns | Allocates new Method copy |
| Proxy method dispatch | ~15 ns | Handler + Method.invoke overhead |

**5 nguyên tắc khắc cốt:**

1. **Cache Method/Field objects** — `getDeclaredMethod()` allocates + linear search. Store trong static field hoặc Map.
2. **`setAccessible(true)` cho hot path** — tiết kiệm access check. JDK 9+: cần `--add-opens`.
3. **Inflation tự động sau 15 calls** — đừng lo reflection "chậm" cho framework code gọi triệu lần. Nó tự optimize.
4. **JDK Proxy chỉ cho interface** — cần proxy class → CGLIB/ByteBuddy. Spring Boot default = CGLIB.
5. **MethodHandle cho performance-critical** — access check 1 lần, JIT inline như direct call. Future của Java reflection.

> [!TIP]
> Một câu để nhớ: *Reflection là "meta-programming engine" của Java — chậm lần đầu, tự optimize lần sau. Dynamic Proxy biến interface thành "programmable dispatch" — nền tảng của mọi framework (Spring AOP, Feign, Hibernate lazy). Hiểu cả hai là hiểu tại sao framework "magic" hoạt động.*
